# hypr/

Copy of the load-bearing part of `~/.config/hypr` (Lua-configured Hyprland,
COPR `lionheartp/Hyprland`), mirrored at the same relative paths so the
installer can drop this tree straight in.

| Repo path | Goes to | Notes |
|---|---|---|
| `hyprland.lua` | `~/.config/hypr/hyprland.lua` | main config. Edit points on a fresh machine: the `hl.monitor` block (hardcoded `DP-1`/`DP-2` names+modes), `hl.env("LIBVA_DRIVER_NAME","nvidia")` (only if you have an NVIDIA GPU), `kb_layout = "us,de"`, and the `flatpak run com.spotify.Client` / `vesktop` / `flatpak run org.signal.Signal` / `tuned-adm profile throughput-performance` exec-once app choices. Guards `plugin.hyprexpo.*` behind `plugin_loaded("hyprexpo")` so it doesn't error before the plugin is added. |
| `hyprland-gui.lua` | `~/.config/hypr/hyprland-gui.lua` | `require("hyprland-gui")`'d from `hyprland.lua`. Normally regenerated by the HyprMod GUI tool; tiny, safe to hand-copy if HyprMod isn't installed. |
| `hypridle.conf` | `~/.config/hypr/hypridle.conf` | |
| `hyprlock.conf` | `~/.config/hypr/hyprlock.conf` | `hyprlock-colors.conf` (generated by `scripts/wallpaper-apply.sh` on every wallpaper switch) is NOT here -- it's regenerated, not config. |
| `dotfiles/ghostty/config.ghostty` | `~/.config/hypr/dotfiles/ghostty/config.ghostty` | `~/.config/ghostty` is a symlink to `~/.config/hypr/dotfiles/ghostty` on the live system -- the installer recreates that symlink (see below), it does not copy a second ghostty tree. |
| `dotfiles/ghostty/themes/caelus` | `~/.config/hypr/dotfiles/ghostty/themes/caelus` | hand-authored ghostty theme. `themes/matugen` (the rendered output) is excluded. |
| `dotfiles/ghostty/matugen/theme` | `~/.config/hypr/dotfiles/ghostty/matugen/theme` | ghostty's matugen template -- also the `[templates.ghostty]` `input_path` in `dotfiles/matugen/config.toml`, resolved through the symlink above. |
| `dotfiles/rofi/{config.rasi,caelus.rasi,keybinds.rasi}` | `~/.config/hypr/dotfiles/rofi/{...}` | `~/.config/rofi` is likewise a symlink to `~/.config/hypr/dotfiles/rofi`. |

## Symlinks the installer must recreate, not copy

Three scripts under `~/.config/hypr/scripts/` are symlinks INTO this repo's
own top-level `scripts/`, and two `~/.config` entries are symlinks into
`hypr/dotfiles/` above. Nothing extra needs to exist in the repo for either
-- the installer just needs to `ln -sf` them after placing this tree. Full
source -> target list: `SCRATCH/links.md` (from the audit that produced this
directory) or, in short:

```
~/.config/hypr/scripts/keybinds.sh    -> <repo>/scripts/keybinds.sh
~/.config/hypr/scripts/mic-toggle.sh  -> <repo>/scripts/mic-toggle.sh
~/.config/hypr/scripts/screenshot.sh  -> <repo>/scripts/screenshot.sh
~/.config/ghostty                     -> ~/.config/hypr/dotfiles/ghostty
~/.config/rofi                        -> ~/.config/hypr/dotfiles/rofi
```

## Excluded (junk/generated)

`*.bak*` editor/HyprMod backups, `hyprlock-colors.conf` (regenerated per
wallpaper), `hyprmod/` (HyprMod's own profile bookkeeping -- its
`profiles/<id>/hyprland-gui.lua` is the same content as the copied
`hyprland-gui.lua`, so nothing is lost), `dotfiles/ghostty/themes/matugen`
(rendered output), `dotfiles/ghostty/config.ghostty.bak-*`, the standalone
`~/.config/hypr/install.sh` and `README.md` (superseded by the repo-root
installer; their COPR list, cursor-theme fetch, hyprpm hyprexpo add/enable
sequence and wayvibes build steps were folded into it instead of copied
verbatim).

See `dotfiles/README.md` for the rest of the rice (matugen pipeline, btop,
cava, yazi, nvim, vesktop, spicetify, fetchit).
