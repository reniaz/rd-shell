# dotfiles/

The rest of the matugen-driven rice, mirroring `~/.config` paths so the
installer can `cp`/`ln` each tree straight into place. Ghostty and rofi are
NOT here -- both live under `hypr/dotfiles/` because `~/.config/ghostty` and
`~/.config/rofi` are themselves symlinks into `~/.config/hypr/dotfiles/` on
the live system (see `hypr/README.md`). Every path below is a matugen
`input_path` (or something a matugen `input_path` needs at runtime) --
missing any one of them makes `matugen` fail its whole run on a fresh
machine, not just skip one app.

| Repo path | Goes to | What it is |
|---|---|---|
| `matugen/config.toml` | `~/.config/matugen/config.toml` | the render pipeline itself: every `[templates.*]` below, plus the custom ANSI palette |
| `btop/matugen/matugen.theme` | `~/.config/btop/matugen/matugen.theme` | btop theme template |
| `cava/matugen/config` | `~/.config/cava/matugen/config` | cava `[color]` template (cava has no include directive, so this is the whole config) |
| `yazi/matugen/theme.toml` | `~/.config/yazi/matugen/theme.toml` | yazi theme template |
| `nvim/matugen/colorscheme.lua` | `~/.config/nvim/matugen/colorscheme.lua` | renders `colors/matugen.lua` on every wallpaper switch |
| `nvim/lua/matugen_watch.lua` | `~/.config/nvim/lua/matugen_watch.lua` | re-sources the rendered colorscheme live via `vim.uv.fs_event`, only while `matugen` is the active colorscheme |
| `vesktop/themes/matugen/caelus-accent.css` | `~/.config/vesktop/themes/matugen/caelus-accent.css` | Vesktop accent template |
| `vesktop/themes/system24-caelus.theme.css` | `~/.config/vesktop/themes/system24-caelus.theme.css` | the base theme the accent theme sits beside (enabled separately in Vesktop, not `@import`ed) |
| `spicetify/Themes/caelus24/{theme.js,user.css,color.ini}` | `~/.config/spicetify/Themes/caelus24/{...}` | hand-authored spicetify theme |
| `spicetify/Themes/caelus24/matugen/caelus-accent.css` | `~/.config/spicetify/Themes/caelus24/matugen/caelus-accent.css` | its accent template, rendered to `~/.cache` and copied into xpui |
| `fetchit/init.lua`, `fetchit/logos/logo.txt` | `~/.config/fetchit/{init.lua,logos/logo.txt}` | fetchit config; the `fetchit` binary itself has no known source repo -- build/obtain it yourself, this only places its config |

Not here, and never committed anywhere in this repo: every matugen *output*
(`~/.config/{btop/themes,cava/config,yazi/theme.toml,nvim/colors/matugen.lua,
vesktop/themes/caelus-accent.theme.css}`, `~/.cache/caelus24/*`) and Vesktop's
stock `buttons.css`/`game.css`/`store.css`/`shared_global.css` (not
authored here, and not `@import`ed by `system24-caelus.theme.css`, which
pulls its base from the upstream system24 CDN URL instead). All of these are
either regenerated by matugen on first run or simply unused by the kept
theme.

## nvim wiring

Two lines in `~/.config/nvim/init.lua` are what make nvim use this theme;
without them the rendered colorscheme file exists but nothing loads it:

```lua
require("matugen_watch")
if not pcall(vim.cmd.colorscheme, "matugen") then
  vim.cmd.colorscheme("gruvbox-material")
end
```

`gruvbox-material` is the user's own fallback scheme (already set up
elsewhere in `init.lua`, untouched by this repo) -- it's what nvim falls
back to if the matugen render is missing or fails to load, so a fresh
checkout never leaves nvim with no colorscheme applied at all.
